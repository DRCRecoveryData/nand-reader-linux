What this is

The reader is a Cypress FX2 / EZ-USB style part (VID:PID 03eb:5903) with an FPGA in front of the NAND. The host streams a bitstream and a small micro-op program, then reads the die. This project reproduces that protocol on Linux and drives real 2 KB NAND pages.

Windows vs Linux

Under Windows, the vendor app NAND_Reader.exe (via FlashReader2.sys) performs the ID leg and then stops: because 89c40832 is not in its chip database, its Read/Conf controls stay disabled and it never issues a page read.

The Linux driver speaks the same wire protocol (verified byte-for-byte against the captured vendor traffic) but does not stop at the un‑recognised ID — it drives the vendor READ micro-op directly.

Quick start

./nand check                       # payload status
./nand probe                       # safe bring-up probe
./nand info                        # describe the USB device
./nand power --cycle --cv 330      # raise rail, read DAC echo, lower
./nand id --cycle                  # expect 89 c4 08 32
./nand readp 1010 1026 2040 --out out/      # read single pages
./nand readp 1013 --votes 15 --out out/     # majority-vote a marginal page
./nand readp 1026 --bank 2                  # second bank

How the read works

Each page is read with the vendor's READ program (NAND_Reader.exe FUN_0045e3d0): reset, three row-address cycles, two column cycles, then 11 30 (READ). The page number is carried in the 32-byte control block, not in the row cycles or the trailer. The FPGA emits exactly one unit per power-up, so every page needs its own YKUSH cold cycle (~35 s/page).

What the chip contains

  • 2 KB pages in 8-page blocks: one erased page, then seven data-or-blank pages. Erased pages land on multiples of 8.
  • Programmed data is high-entropy (~7.4 bits/byte) — scrambled or encrypted; main and spare alike. This is a raw-cell read, not a decoded image.
  • Banks 1 and 2 return different, valid data; banks 3–4 return 30 30 30 … because the FPGA leaves them unselected.
Cleaning bit errors. A few cells per page are marginal and flip single bits between reads. --votes N reads the page N times and keeps the per-bit majority. At 15 votes the page head is stable; ~12 bits per page stay undecided even at 31 votes — the raw-read floor without ECC.

Limits (hardware, not code)

  • One page per power cycle — no fast streaming.
  • Banks 3 and 4 are never selected by the FPGA.
  • No usable ECC block in the spare area; content is encrypted/scrambled.
  • No write / erase implemented.
Recovered images. Dumped pages are written wherever readp --out DIR points, as one page_<n>.bin per page. Re-read any page with --votes 15 for a cleaner copy.

How it was made to work

  • Protocol from the reference doc + static analysis; libusb on EP2 OUT / EP6 IN, YKUSH power-cycle for recovery.
  • Chip presence: rail ADC tracks setpoint; ID answers 89 c4 08 32.
  • Capture: ran the real vendor binary under Wine with its device I/O hooked — proved the Linux frames match byte for byte.
  • Disassembly of the READ path: found the 0x30 READ program and control-block layout.
  • Empirical sweep: the encoding that reproduces bit-exactly across cold cycles puts the page in the control block.
  • Verified real flash via the 8-page block cadence.
